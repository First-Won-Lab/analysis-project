# 유지보수 지침

이 문서는 저장소를 고치는 사람(사람 또는 AI)을 위한 작업 지침입니다.

## 1. 핵심 원칙

1. **계산 로직은 두 곳에 있다.** 웹앱 `assets/analysis.js`와 로컬 스크립트 `python/auto_ver4.py`는 같은 입력에 같은 결과를 내야 한다. 한쪽을 고치면 다른 쪽도 같은 커밋에서 고친다.
2. **규칙의 기준은 `tests/cases.json`이다.** 파일명 규칙, 피크 기준, 쌍 구성, 통계 정의를 바꿀 때는 이 파일의 케이스부터 고치고, 두 언어의 테스트를 모두 통과시킨다.
3. **측정 원본 데이터는 커밋하지 않는다.** `.gitignore`가 `*.csv`를 막고 있다. 테스트용 데이터는 `cases.json` 안에 짧게 인라인으로 넣는다.
4. **빌드 단계 없음.** 순수 HTML/CSS/JS로 둔다. 외부 라이브러리는 Plotly(cdnjs, 버전 고정) 하나만 쓴다.

## 2. 현재 분석 정의

### 2-1. 분석 정의 v2 — 대역별 공진 dip (기본)

| 항목 | 정의 | 코드 (JS / Python) |
|---|---|---|
| 입력 열 | A열 = 주파수(Hz, 오름차순), B열 = Return Loss(dB). 숫자로 읽히지 않는 행은 건너뜀 | `parseCsv` / `read_curve` |
| dip | 국소 최저점 중 **돌출도 ≥ 최소 돌출도(기본 3 dB)**. 돌출도 = min(왼쪽 최고점, 오른쪽 최고점) − 최저점, 각 방향 최고점은 이 점보다 낮은 점(또는 끝)을 만날 때까지의 최댓값 | `findDips` / `find_dips` |
| 대역 | R1 < 450 ≤ R2 < 1100 ≤ R3 < 2000 ≤ R4 (MHz, 경계는 설정에서 변경) | `bandRanges` / `band_ranges` |
| 대역 피크 | 대역 안에서 돌출도가 가장 큰 dip(동률이면 낮은 주파수). 위치 · 깊이는 주변 3점 포물선 보간, 반치폭 = 최저점+돌출도/2 높이의 폭(측정점 기준) | `bandPeak` / `band_peak` |
| Δf 최저점 | f원 − f무 (Hz, **+ 오른쪽·고주파 / − 왼쪽·저주파**) | `compareBands` / `compare_bands` |
| Δf 모양정렬 | 무표정 dip 주변 곡선(반폭 W = max(30 MHz, 반치폭 × 1.5))을 원상태 곡선 위에서 측정 간격 단위로 ±300 MHz(대역 안) 밀며 **정규화 상관계수(평균 제거)** 최대 지점 → 포물선 보간 | `shapeShift` / `shape_shift` |
| 깊이 차 | dB원 − dB무 (**−면 더 깊어짐**) | |
| 돌출도 차 | 돌출도원 − 돌출도무 (**+면 더 뚜렷해짐**). 곡선 전체가 위아래로 뜨는 영향을 뺀 공진 자체의 변화 | |
| ⚠ 이동량 불일치 | \|Δf 최저점 − Δf 모양정렬\| > max(10 MHz, \|Δf 최저점\| × 15%) → `status = 'mismatch'`. '불일치 제외' 통계에서만 뺌 | |
| ◐ 모양 변화 | 모양정렬 상관계수 < 0.9 → `shapeChanged`. 정보용 표시, 통계에서 빼지 않음 | |
| 피크 없음 | 무표정 · 원상태 중 한쪽이라도 그 대역에 dip이 없으면 `status = 'missing'`, 그 대역 통계에서만 제외 | |
| 통계 | 대역 × 표정 · 부위별 평균, 표본표준편차(n−1): Δf 최저점, \|Δf\| 최저점, Δf 모양정렬, 깊이 차, 돌출도 차, 불일치 제외 Δf 2종 | `bandStats` / `band_stats` |

결정 배경 (2026-10, 데이터 899개 분석):
- dip이 R1~R4 네 대역에 몰려 있고(파일당 평균 4.0개), 대역 사이에는 거의 없다. 대역 출현율: R1 97%, R2 100%, R3 99.8%, R4 81%.
- 전체 최저점 하나만 쓰면 attempt마다 다른 공진이 잡혀 비교가 섞인다(예: 놀람·입 \|Δf\| 562 ± 494 MHz → 대역별 R2 +161 ± 24 MHz).
- 모양정렬은 SSD(제곱오차)보다 정규화 상관이 평평한 구간에 잘못 맞는 일이 적었고, 비교 창 1.5 × 반치폭에서 두 방식 차이가 가장 작았다(R2 중앙값 2.8 MHz).
- '의심'을 하나로 묶으면 37%가 걸려(모양만 바뀐 경우, 이동이 커서 10 MHz가 상대적으로 작은 경우 포함) 불일치(상대 허용)와 모양 변화로 나눴다.

설정값은 `DEFAULT_SETTINGS`(두 언어)에 있다. 웹 화면과 CLI(`--bounds`, `--min-prom`)에서는 대역 경계와 최소 돌출도만 바꾼다. 결과 CSV 첫 줄에 사용한 설정을 기록한다.

### 2-2. 이전 방식 — 전체 최저점 (참고용)

| 항목 | 정의 |
|---|---|
| 피크 | B열 전체 구간 최저값과 그 행의 A열 값. 동률이면 먼저 나온 행 (`auto_ver3` 기준) |
| 비교값 | `\|Δf\| = \|f원 − f무\|`, `\|ΔdB\| = \|dB원 − dB무\|` (절대값) |

### 2-3. 공통 규칙

| 항목 | 정의 |
|---|---|
| 비교 대상 | 같은 표정 · 부위 · attempt의 무표정(`무`) 파일 1개 + 원상태 파일 1개 |
| 차단 (2개 비교) | 파일명 규칙 불일치 / 둘 다 무표정 / 둘 다 원상태 / 표정 · 부위 · attempt 불일치 → 비교하지 않고 원인 파일명 표시 |
| 제외 (일괄) | 짝 없음 / 파일명 규칙 불일치 / 데이터 추출 실패 → 목록으로 표시 · CSV 저장 |
| 중복 | 같은 파일명은 한 번만 계산 (`통합` 폴더와 `종합` 폴더를 함께 올렸을 때) |
| attempt 표 | 비교군별로 쌍이나 짝 없는 파일이 있는 attempt를 행으로 나열. CSV 열 = 전체 attempt 합집합, 짝 없는 칸 = `짝 없음`, 대역 dip 없음 = `피크 없음`, 파일이 아예 없으면 빈칸 |
| CSV 형식 | 웹 다운로드와 Python 저장 파일이 같은 형식 (`bandPairRows` · `bandStatRows` · `bandMatrixRows` ↔ `band_pair_rows` · `band_stat_rows` · `band_matrix_rows`) |

파일명 정규식 (두 언어 동일, 비교 전에 NFC 정규화):

```
(놀|화|웃)\s*(눈|입|볼)\s*(\d+)(\s*무)?\s*\.csv$   (대소문자 무시)
```

## 3. 파일별 역할

| 파일 | 역할 | 고칠 때 주의 |
|---|---|---|
| `index.html` | 화면 구조 | 요소 `id`는 `app.js`가 참조함 |
| `assets/analysis.js` | 계산 전용 (DOM 없음, 브라우저/Node 모두 로드 가능) | Python과 결과 일치 |
| `assets/app.js` | 업로드, 그래프, 표, 다운로드 | 계산을 여기 넣지 말고 `analysis.js`에 |
| `assets/style.css` | 색 토큰(라이트/다크), 레이아웃 | 그래프 색도 CSS 변수에서 읽음 |
| `python/auto_ver4.py` | 로컬 일괄 분석, CSV 저장 | 표준 라이브러리만 사용 |
| `tests/cases.json` | 공통 케이스 | 규칙 변경의 출발점 |
| `tests/test_auto_ver4.py` | Python 테스트 | |
| `tests/analysis.test.html` | JS 테스트 (브라우저) | 제목이 `PASS` / `FAIL`로 바뀜 |
| `docs/images/` | README 스크린샷 | UI가 바뀌면 다시 찍기 |

색 규칙:
- 그래프 색은 검증된 팔레트 그대로 둔다: 무표정 = 파랑(`--series-neutral`), 원상태 = 주황(`--series-expressive`), 통계 막대 = `--chart-bar`. 두 계열색의 역할을 바꾸지 않는다.
- 나머지 화면(배경, 카드, 탭, 버튼)은 파스텔 톤 토큰(`--accent`, `--accent-soft`, `--peach-soft`, `--mint-soft`, `--banner-*` 등)을 쓴다. 라이트/다크 값은 `style.css` 맨 위에서 함께 고친다.
- 글꼴: 제목·숫자 강조는 Google Fonts `Jua`, 본문·표는 `Noto Sans KR`.
- 상단 배너의 강아지·고양이는 `index.html` 안의 인라인 SVG 일러스트(직접 그림, 외부 이미지 없음)다. 움직임은 `prefers-reduced-motion`이면 꺼진다.

## 4. 작업 절차

1. `main`에서 브랜치를 만든다 (`git switch -c feat/설명`).
2. 규칙이 바뀌는 작업이면 `tests/cases.json`부터 고친다.
3. `analysis.js`와 `auto_ver4.py`를 함께 고친다.
4. 아래 **검증 체크리스트**를 모두 확인한다.
5. 커밋 메시지는 무엇을 왜 바꿨는지 한 줄로 쓰고, 필요하면 본문에 적는다.
6. `main`에 병합해 push하면 GitHub Pages에 1~2분 안에 반영된다.

## 7. 새 데이터 / 새 규칙이 생기면

| 상황 | 할 일 |
|---|---|
| 새 측정 날짜 · 새 피험자 | 파일명 규칙만 맞으면 코드 수정 없음 |
| 새 표정 · 부위 추가 | 정규식, `EXPRESSIONS`/`PARTS`, 이름 표(`*_NAMES`)를 두 언어에서 함께 수정 + `cases.json` 케이스 추가 |
| CSV 열 순서 변경 | 두 언어의 피크 추출 함수에서 열 번호 수정 + `csv_peaks` 케이스 추가 |
| 피크 · 이동 기준 변경 | §2-1 표 갱신 → `cases.json`(합성 곡선 `v2_synthetic` 등) → 두 언어 `DEFAULT_SETTINGS`와 구현 → 화면의 '분석 설정 · 피크 정의' 목록 → 실제 데이터로 웹/Python CSV 비교 |
| 대역 수 변경 (예: 5개) | 경계 배열 길이만 늘리면 계산은 동작함. 웹 설정 입력칸(`set-b*`), 대역 색(`--band-*`), CLI `parse_bounds`의 개수 검사를 함께 수정 |
